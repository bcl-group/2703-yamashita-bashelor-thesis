# NumPyだけで実装するRNN（sin波の予測）

卒業研究用。PyTorch / Keras / TensorFlow を**一切使わず**、NumPyの基本的な配列演算だけで
RNN（Elman型）の順伝播・逆伝播（BPTT）・パラメータ更新を実装したもの。

## データの説明（訓練データ・検証データ・正解データとは何か）

### まず全体像

元になるのは**1本のノイズ入りsin波**だけ。長さ201点の数字の列である。

```
f = [0.0196, 0.0414, 0.0980, 0.1925, ... ]   ← 201個の数字（時刻0〜200の波の高さ）
```

これをそのまま学習に使うのではなく、**「問題カード」を176枚作る**。
1枚のカードは「問題（25個の数字）」と「答え（次の1個の数字）」のセットになっている。

```
カード0 : 問題 = f[0]〜f[24] の25個   →  答え = f[25]
カード1 : 問題 = f[1]〜f[25] の25個   →  答え = f[26]
カード2 : 問題 = f[2]〜f[26] の25個   →  答え = f[27]
   ...
カード175: 問題 = f[175]〜f[199]の25個 →  答え = f[200]
```

窓を1つずつ右にずらしながら作るので、201 - 25 = **176枚**できる。
この「問題」が**入力データ**、「答え」が**正解データ**である。

実際の数字で見ると:

```
カード0 の問題（先頭3個だけ表示）: 0.0196, 0.0414, 0.0980, ...  答え: 0.9823
カード1 の問題（先頭3個だけ表示）: 0.0414, 0.0980, 0.1925, ...  答え: 0.9842
```

### 176枚のカードを2つに分ける

```
カード0 〜 カード139   (140枚)  →  訓練データ   … 学習に使う
カード140 〜 カード175  (36枚)  →  検証データ   … 学習には使わない
```

時系列データなので、**シャッフルせずに前から順番に**分ける。
ランダムに分けると「未来の答えを見てから過去を予測する」ことになってしまうため。

> 細かい注意: カードは窓をずらして作っているので、隣り合うカードは中身が重なっている。
> 訓練データが見ているのは `f[0]`〜`f[164]`、検証データが使うのは `f[140]`〜`f[200]` なので、
> 問題文の一部（`f[140]`〜`f[164]`）は訓練でも登場している。
> ただし検証データの**答え**にあたる `f[165]` 以降は、訓練に一度も使われていない。

### 用語とコード上の変数の対応

| 呼び方 | 変数名 | shape | 中身 | 学習（重みの更新）に使うか |
|---|---|---|---|---|
| 元データ | `f` | (201,) | ノイズ入りsin波そのもの | 直接は使わない（カードの材料） |
| 入力データ | `x` | (176, 25, 1) | 176枚分の「問題」 | — |
| 正解データ | `t` | (176, 1) | 176枚分の「答え」 | — |
| 訓練用の入力 | `x_train` | (140, 25, 1) | 前140枚の問題 | **使う** |
| 訓練用の正解 | `t_train` | (140, 1) | 前140枚の答え | **使う** |
| 検証用の入力 | `x_val` | (36, 25, 1) | 後ろ36枚の問題 | 使わない |
| 検証用の正解 | `t_val` | (36, 1) | 後ろ36枚の答え | 使わない |
| 答え合わせ用の波 | `sin_true` | (201,) | **ノイズなし**の理想のsin波 | 使わない（最後の図の点線） |

`x.shape = (176, 25, 1)` の意味:

```
(176,  25,   1)
  │     │    └─ 各時刻の入力が1個の数字であること（input_dim）
  │     └────── 1枚のカードに問題が25個あること（時系列の長さ）
  └──────────── カードが176枚あること（サンプル数）
```

### それぞれが何のために使われるか

**訓練データ（140枚）** — これだけが重みの更新に使われる。
モデルに問題（25個の数字）を見せて予測させ、答え（`t_train`）とのズレを計算し、
そのズレが小さくなるように重み `W_xh, W_hh, b_h, W_hy, b_y` を書き換える。
この「ズレ」が **loss（訓練損失）**。

**検証データ（36枚）** — 重みの更新には**一切使わない**。
モデルに解かせて答え合わせをするだけ。この点数が **val_loss（検証損失）**。
訓練データは何度も見せるので、モデルが「丸暗記」してしまう可能性がある。
一度も学習に使っていないデータでも当てられるかを確認するために分けておく。

- `loss` だけ下がって `val_loss` が下がらない → 丸暗記している（過学習）
- 両方下がっている → 波の規則そのものを学習できている

本実装では両方 0.0013 前後まで下がるので、丸暗記ではなく規則を学習できている。

**`sin_true`（ノイズなしsin波）** — 最後の図でだけ使う。
学習にも検証にも使わない。学習データにはノイズが乗っているので、
「本当はこういう波だった」という理想の形と、モデルが描いた波を見比べるための基準線
（`prediction.png` の灰色の破線）。

### 最後の図でやっていること

`prediction.png` は、上の検証データとはまた別の評価をしている。

1. モデルに**最初の25点だけ**（カード0の問題）を渡して、次の1点を予測させる
2. その**予測値を入力の末尾に足して**、1つ古い点を捨てる
3. その新しい25点でまた次の1点を予測する ... を176回繰り返す

つまり26点目から先は、**モデルが自分の予測だけを頼りに波を描き続けている**。
本物のデータを一切見ずにsin波の形を保てるなら、
モデルは「周期的に上下する」という規則を本当に理解している、と言える。

## 処理の流れ

```
toy_problem()        sin波＋ノイズを生成                          sin_wave.py
  ↓
create_dataset()     25点 → 次の1点 の形に変換                    rnn/data.py
                     x:(176,25,1)  t:(176,1)
  ↓
split_in_order()     先頭80%を訓練、残り20%を検証                  rnn/data.py
  ↓
SimpleRNN            W_xh, W_hh, b_h, W_hy, b_y を初期化          rnn/model.py
  ↓
forward()            時刻ごとに h = tanh(x_t W_xh + h_prev W_hh + b_h)  rnn/model.py
  ↓
mean_squared_error() 損失                                         rnn/losses.py
  ↓
backward()           BPTT。時間を遡って誤差を伝播させ、勾配を求める  rnn/model.py
  ↓
optimizer.step()     SGD または Adam でパラメータ更新              rnn/optimizers.py
  ↓
generate_sequence()  予測値を入力に戻しながらsin波を生成            sin_wave.py
  ↓
plot_results()       学習曲線と予測結果を描画                      sin_wave.py
```

`create_dataset()` から `optimizer.step()` までの繰り返しは `rnn/train.py` の `train()` にまとめてある。

## 資料の式とコードの対応

| 資料の式 | 内容 | コード |
|---|---|---|
| (5.4) | `h(t) = tanh(W x(t) + U h(t-1) + b)` | `forward()` の `np.tanh(p)` |
| (5.5)(5.15) | `y = V h(t) + c`（線形） | `forward()` の `h_last @ self.W_hy + self.b_y` |
| (5.16) | 二乗誤差 | `mean_squared_error()` |
| (5.18) | `e_o = g'(q) ⊙ (y - t)` | `backward()` の `e_o` |
| (5.17) | `e_h(t) = f'(p) ⊙ V^T e_o` | `backward()` の `e_h` 初期化 |
| (5.22)(5.23) | `e_h(t-1) = e_h(t) ⊙ (U f'(p(t-1)))` | `backward()` のループ最終行 |
| (5.10)(5.12)(5.13) | `∂E/∂W`, `∂E/∂U`, `∂E/∂b` | ループ内の `dW_xh`, `dW_hh`, `db_h` |
| (5.11)(5.14) | `∂E/∂V`, `∂E/∂c` | `dW_hy`, `db_y` |
| (5.24)-(5.28) | パラメータ更新 | `class SGD` |
| 5.1.4 (p.265) | 直交行列による初期化 | `SimpleRNN(init='orthogonal')` |

資料の記号 `W, U, V, b, c` は、コード内では役割が分かるように
`W_xh, W_hh, W_hy, b_h, b_y` という名前にしている（対応はコメントに併記）。

## 最適化アルゴリズムについて

最初は最も基本的な**SGD**（`パラメータ -= 学習率 * 勾配`）で実装した。
SGDでも「次の1点を予測する」学習自体は成立する（損失は 0.003 程度まで下がる）が、
**予測値を入力に戻して波形を生成させると形が崩れた**ため、
GitHub版と同じ設定（`lr=0.001, betas=(0.9,0.999), amsgrad=True`）のAdamも自作し、
こちらをデフォルトにしている。

SGDで試す場合は `sin_wave.py` の `main()` の

```python
optimizer = Adam(model, lr=0.001, beta1=0.9, beta2=0.999, amsgrad=True)
```

を

```python
optimizer = SGD(lr=0.05)
```

に変えればよい。

## 実験して分かったこと（パラメータの比較）

条件は hidden_dim=50, batch_size=100。
`gen_mse` は、生成した波形と正解sin波との二乗誤差（小さいほど良い）。

まず最適化アルゴリズムの比較（seed=123）:

| 最適化 | 初期化 | lr | epochs | val_loss | gen_mse |
|---|---|---|---|---|---|
| SGD | simple | 0.05 | 1000 | 0.0042 | 0.664 |
| SGD | simple | 0.5 | 1000 | 0.0031 | 0.785 |
| SGD | orthogonal | 0.05 | 1000 | 0.0017 | 0.608 |
| SGD | orthogonal | 0.2 | 1000 | 発散(nan) | — |
| Adam | orthogonal | 0.001 | 1000 | 0.0016 | 0.736 |
| **Adam** | **simple** | **0.001** | **1000** | **0.0014** | **0.075** ← 採用 |

次に初期化とエポック数の比較（Adam lr=0.001、seed=123/42/7 の3回）:

| 初期化 | epochs | val_loss平均 | gen_mse（3回） | 平均 |
|---|---|---|---|---|
| **simple** | **1000** | **0.00122** | 0.075 / 0.040 / 0.010 | **0.042** |
| simple | 2000 | 0.00122 | 0.006 / 0.436 / 0.015 | 0.153 |
| orthogonal | 1000 | 0.00176 | 0.736 / 0.070 / 0.064 | 0.290 |
| orthogonal | 2000 | 0.00168 | 0.045 / 0.149 / 0.197 | 0.130 |

- `val_loss`（次の1点の予測精度）が良くても `gen_mse`（波形の生成）が良いとは限らない。
- 長く学習させるとシードによって生成が大きく崩れることがある。
  資料が EarlyStopping を使って95エポック程度で止めているのは、これを防ぐ意味がある。
- 資料どおりの直交初期化より、単純な初期化のほうが今回は安定していた。
  ただし**シードによるばらつきが大きく、3回の試行で断定できるほどの差ではない**。
  資料に合わせたい場合は `SimpleRNN(..., init='orthogonal')` にすればよい。

### 10シードでの比較（2026-09-30、`sin_wave_eval.py`）

上の3シードの比較では結論が出せなかったので、EarlyStopping（ES）を実装したうえで
seed=0〜9 の10回ずつ回して比べた。ES は資料と同じ patience=10。

| 初期化 / 学習の止め方 | 平均エポック | val_loss平均 | gen_mse平均 | 中央値 | 最大 | gen_mse<0.05 |
|---|---|---|---|---|---|---|
| simple / ES | 202 | 0.00165 | 0.233 | 0.190 | 0.583 | 1/10 |
| simple / 1000 | 1000 | 0.00140 | 0.144 | 0.042 | 0.670 | 6/10 |
| orthogonal / ES | 433 | 0.00206 | 0.376 | 0.199 | 1.186 | 3/10 |
| **orthogonal / 1000** | 1000 | 0.00166 | **0.041** | **0.030** | **0.133** | **7/10** |

- **直交初期化で1000エポック回し切るのが、生成が最も良く、最も安定していた**（最悪でも 0.13）。
  3シードで「単純な初期化のほうが安定」と見えたのは、シードの偶然だった。
- **ESを入れると生成はむしろ悪くなった。** ESは val_loss（1点先の予測）で止めるが、
  1点先の予測が十分でも、自分の予測を入力に戻す生成が安定するにはもっと学習が要る。
  上の「長く学習すると崩れる」という見立ても、10シードでは支持されなかった。
- 資料の図5-5のように正解とほぼ重なる波形（gen_mse が 0.01 程度以下）は、どの条件でも一部のシードでしか出ない。
  資料の図は条件の良い1回分と考えるのが自然。

実行方法（4条件×10シードを並列に回す。1分半ほど）:

```bash

```

### 教科書のコード（PyTorch / Keras）との比較と、差の原因（2026-09-30）

`textbook_eval.py` で、教科書のコードをライブラリを使ったまま同じ10シードで回した

| 実装 / 止め方 | gen_mse中央値 | 最大 | <0.05 |
|---|---|---|---|
| 教科書 PyTorch / ES | 0.016 | 0.844 | 8/10 |
| 教科書 PyTorch / 1000 | 0.006 | 0.032 | 10/10 |
| 教科書 Keras / ES | 0.006 | 0.655 | 8/10 |
| 教科書 Keras / 1000 | 0.002 | 0.041 | 10/10 |

NumPy版（上の表）より明らかに良かったので、教科書のコードとの違いを1つずつ直して比べた（すべて1000エポック）。

| NumPy版の初期化 / AMSGrad | gen_mse中央値 | 最大 | <0.05 |
|---|---|---|---|
| orthogonal / 以前の実装 | 0.030 | 0.133 | 7/10 |
| orthogonal / PyTorchと同じ | 0.007 | 0.129 | 9/10 |
| **xavier / 以前の実装** | **0.0015** | **0.016** | **10/10** |
| xavier / PyTorchと同じ | 0.006 | 0.060 | 9/10 |
| xavier / PyTorchと同じ / ES | 0.026 | 0.452 | 6/10 |
| simple / PyTorchと同じ | 0.281 | 0.825 | 0/10 |

- **主な原因は W_xh（入力→隠れ層）の初期値だった。** 以前の `orthogonal` は標準偏差 sqrt(1/n_in) = 1 で、
  教科書（PyTorch `xavier_normal_` / Keras `glorot_normal`）の sqrt(2/(n_in+n_out)) ≒ 0.20 の約5倍だった。
  教科書と同じにする `init='xavier'` を追加した。
- AMSGrad も教科書（PyTorch）と違っていた。以前は補正後の v_hat の最大値を保持していたが、
  PyTorch は補正前の v の最大値を保持してから補正する。`Adam(amsgrad_raw=True)`（既定）で PyTorch と同じにした。
  こちらは xavier と組み合わせると差がはっきりしない（10シードでは誤差の範囲）。
- **両方を教科書に合わせた「xavier / PyTorchと同じ」は中央値 0.006 で、教科書の PyTorch 版と同じ水準になった。**
  NumPy版は教科書を再現できている。
- ライブラリ版・NumPy版とも、ES を入れるとまれに大きく崩れる。
- seed=123・ES あり（教科書と同じ条件）で3つの実装の生成波形を並べた図:
  `results/sin_wave/textbook_vs_numpy_seed123.png`（`python -X utf8 textbook_eval.py plot` で作り直せる）。
  gen_mse は PyTorch 0.0059 / Keras 0.0070 / NumPy 0.0041 で、3つとも図5-5 と同等。
  止まったエポックは 131 / 197 / 81 で、教科書（Keras, 95）とは一致しない。
  Keras は同じ seed でも実行ごとに結果が変わる（別の実行では 34 エポック）。
- `sin_wave.py` の `main()` は `init='xavier'` + ES（教科書どおり）にした。seed=123 で64エポックで止まり、
  gen_mse = 0.018。1000エポック回し切ると 0.013。
