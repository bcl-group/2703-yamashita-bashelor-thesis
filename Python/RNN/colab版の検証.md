## 結論（先に要点）

| | 判定 |

| 順伝播（`forward`）の実装 | **正しい**。資料 式(5.4)-(5.7) に忠実 |

**RNNの心臓部（順伝播とBPTT）は正しく書けている。問題はその外側、「何を学習させているか」にある。**

## 1. 最大の問題：教師データが入力と同じ

```python
# 入力系列
train_x = f.reshape(-1,1).astype(np.float32)

# 正解系列
# 同じ時刻の値を教師にする
train_y = f.reshape(-1,1).astype(np.float32)
```

`train_x` と `train_y` が**同じ配列**になっている。
これは「時刻tの値を入れたら、時刻tの値を出せ」という学習であり、
**入力をそのまま出力する（恒等写像）だけの問題**になっている。
「25点を見て次の1点を当てる」という本来の課題ではない。

### 実行して確認した結果

```
入力 train_x[50:55] = [ 0.007  -0.0689 -0.0765 -0.2272 -0.2778]
出力 y[50:55]       = [ 0.0111 -0.0897 -0.0568 -0.2473 -0.2959]

出力と「同じ時刻の入力」とのMSE = 0.000158   ← ほぼ一致している
出力と「次の時刻の入力」とのMSE = 0.003643   ← 23倍ずれている
```

出力が入力とほぼ一致しており、**予測ではなくコピーを学習している**ことが数値で確認できる。

`loss` は 0.112 → 0.0159 と順調に下がるため、
**画面上は学習が成功しているように見えてしまう**のが厄介な点。

### さらに決定的な証拠：再帰結合を切っても悪化しない

再帰の重み `U` を強制的に 0 にして（＝過去の情報を一切使わない、ただの全結合ネットにして）
同じ学習を回した結果:

```
そのまま   : loss = 0.015872
U = 0 に固定: loss = 0.003853   ← むしろ4倍良くなる
```

**再帰結合が役に立っていないどころか、邪魔になっている。**
恒等写像を学ぶのに過去の情報は要らないので、当然の結果である。
つまり現状は「RNNを使う意味のない問題」を解かせている。

### 直すとどうなるか

教師データを1時刻ずらす（`train_y = f[1:]`, `train_x = f[:-1]`）だけでも、
「次の値を予測する」課題になる:

```
予測と正解（次の値）のMSE = 0.001743
```

これはノイズの分散（0.05^2/3 ≒ 0.00083）に近い水準で、まともに予測できている。

## 3. コード上のバグ

### 3-1. `tanh` などのメソッドに `self` が無い（実行するとエラー）

```python
def tanh(x):          # ← self が無い
    return np.tanh(x)
```

`rnn_model.tanh(0.0)` と呼ぶと、`x` の位置に `self` が入ってしまう。実際に確認:

```
rnn_model.tanh(...) -> TypeError: RNN.tanh() takes 1 positional argument but 2 were given
```

`tanh` / `dtanh` / `identity` / `didentity` の4つとも同じ。
ただし `forward` / `backward` の中では `np.tanh(p)` を直接呼んでいて
これらのメソッドを一度も使っていないため、**学習自体は動いてしまう**。

修正するなら、どちらか:

```python
@staticmethod
def tanh(x):
    return np.tanh(x)
```

```python
def tanh(self, x):
    return np.tanh(x)
```

### 3-2. `backward` の中に使われていない行がある

```python
# W
xt = target[t].reshape(-1,1)          # ← どこにも使われていない

# 入力を取得
# xはforward時に保存していないので後で修正   ← コメントが現状と合っていない
self.dW += dp @ self.x[t].reshape(1,-1)
```

- `xt` は代入されるだけで使われない。しかも中身は入力ではなく**教師データ**なので、
  名前と中身が食い違っていて紛らわしい。削除してよい。
- コメントは「保存していないので後で修正」とあるが、`forward` で `self.x.append(xt)` として
  **すでに保存済み**。実際の計算も `self.x[t]` を正しく使えている。コメントだけが古い。

### 3-3. データ型が混在している

```
W: float64    U: float32    V: float64    b: float32    c: float32
```

`U` だけ `Q.astype(np.float32)` としているため。
計算は通るが、型が混ざると意図しない精度低下に気づきにくい。
資料は `f = toy_problem(T).astype(np.float32)` と float32 に統一しているので、
**全部 float32 に揃える**か、**全部 float64（NumPyの既定）にする**かを決めたほうがよい。

### 3-4. `dtanh` を定義したのに使っていない

`backward` の中で `1 - np.tanh(p)**2` を毎回計算し直している。
`self.h[t]` を保存しているので `1 - self.h[t]**2` で済む（`h = tanh(p)` なので同じ値）。
間違いではないが、`tanh` を2回計算していて無駄。

## 4. 正しく書けている点

けなすだけでは公平でないので、確認できた正しい部分も記録しておく。

### 4-1. BPTTの勾配は正しい

数値微分（中心差分）と比較した結果:

```
W : 8.206e-10
U : 4.102e-08
V : 3.164e-10
b : 4.039e-08
c : 3.333e-08
```

相対誤差が 1e-8 以下なので、**BPTTの実装は正しい**と言える。
特に、

```python
dh = self.V.T @ dq + dh_next        # 未来の時刻から来る誤差を足している
dp = dh * (1 - np.tanh(p)**2)
dh_next = self.U.T @ dp             # 1つ前の時刻へ誤差を伝える
```

の部分は、資料 式(5.17) と 式(5.22) をそのまま書き下したものになっていて正しい。
「現在時刻の誤差だけでなく未来から伝播してくる誤差も足す」という
BPTTで最も間違えやすい箇所がきちんと実装できている。

### 4-2. 資料の記号に忠実

`W, U, V, b, c` と `p(t), h(t), q(t), y(t)` を資料の式(5.4)-(5.7)と同じ名前で保持していて、
式とコードの対応が追いやすい。縦ベクトル `(hidden_size, 1)` で持っているのも資料の式どおり。

### 4-3. 初期化が資料5.1.4に沿っている

QR分解による直交初期化は、資料 p.265-266 の「再帰計算部分の重みには直交行列を使う」
という説明に対応している（資料はSVDを例示しているが、QR分解でも直交行列は得られる）。

## 5. 直すべき優先順位

1. **`train_y` を「次の値」にする**（これをやらないと何を学習させても意味がない）
2. **系列を `maxlen=25` で分割する**（資料 p.267。データ数が176に増え、BPTTの遡り幅も適正になる）
3. **出力を最後の時刻だけにする**（資料の `h[:, -1]` に合わせる）
4. **訓練データと検証データに分ける**（資料 p.268）
5. `tanh` 等の `self` を直す / `backward` のデッドコードを消す / dtypeを揃える
6. 最適化を Adam にする（資料 p.270）
7. 予測結果と学習曲線を描く（資料 p.270-272）

1〜4 を直すと、`simple_rnn.py` とほぼ同じ構成になる。
