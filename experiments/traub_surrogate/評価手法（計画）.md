# 評価手法（計画）

代理モデルの精度と速度を、元の微分方程式モデル（以下 ODE）と比べるための評価手法の計画。HH（移植前）と Traub（移植後）の両方を扱う。

- HH（空間形状のない点モデル）: 代理モデルの作り方を確かめる段階。精度は細かく評価する。速度も同じ GPU で測って比べる。2026-11-24 の V100 の結果では、同時に計算するニューロン数 B が小さいと代理モデルが速く（B = 1024 で Markov MLP 76 µs、HH 200 µs）、大きいと HH が速い（B = 65536 で HH が 5〜16 倍速い）。どちらが勝つかを B で分けて示し、理由（HH はカーネル起動、代理モデルは行列積の量）を測って説明する。
- Traub（19 区画）: 卒論の本番。精度と速度の両方で ODE と比べる。

構成: 0 章が全体像、1・2 章が Traub の教師データと学習、3 章が精度、4 章が速度。

経緯: 2026-11-16 に Codex と相談して初版（Traub の学習と評価）を作った。2026-11-20 に HH の評価、ODE との公平な比較、統計の扱い、速度の損益分岐を追加した（小林先生の博論 [11] と文献 [13]〜[24] を参照し、Codex と再度相談）。数値は文献の考え方を当てはめた提案で、断りがなければ論文が推奨している値ではない。

## 0. 評価の全体像

### 0.1 四つの評価

| | 精度 | 速度 |
|---|---|---|
| HH（移植前） | 3.2 節。作り方を決める根拠。Γ とスパイク本数を中心に、ずれの原因（周期の偏り、発火開始の位置）まで調べる | 4.2 節。B ごとにどちらが速いかを示し、その理由を演算量とメモリ転送量（カーネル起動の回数）で説明する。負ける B では、勝つのに必要な刻み幅を見積もる |
| Traub（移植後） | 3.3 節。細胞体のスパイク・バーストと樹状突起の Ca | 4.3 節。同じ精度を満たす最速の ODE と比べる |

### 0.2 正解の取り方

具体例: 今の HH の採点は、教師と同じ陽的 Euler（dt = 0.01 ms）の解を正解にしている。この正解は ODE の出力そのものなので、ODE の誤差は常に 0 になり、ODE と精度を比べられない。

そこで正解を 2 つ持つ。

| 正解 | 作り方 | 分かること |
|---|---|---|
| 教師正解 | 教師と同じ陽的 Euler、dt = 0.01 ms、fp32 | 代理モデルがどれだけ学習できたか（学習誤差） |
| 収束正解 | fp64 の高次の適応刻み解法（例: `scipy.integrate.solve_ivp` の DOP853）で、許容誤差を厳しくしていき、指標（スパイク時刻、Γ）が変わらなくなった解 | ODE と代理モデルを同じ基準で比べられる。Euler dt = 0.01 ms 自体の離散化誤差も分かる |

刻み幅が違う解どうしは、正解の時刻に線形補間して比べる（博論でも適応刻みの RKC 法の解を CN 法の解と線形補間で比べている。[11] p.33 §3.2.7）。段階電流の切り替え時刻、OU 電流の実現値、その補間の仕方は全方式で共有する。

### 0.3 ODE と公平に競争するための約束

機械学習で流体の偏微分方程式を解く論文を調べると、数値解法に勝ったと主張する 76 本のうち 60 本（79%）が弱いベースラインと比べていた [13]。同じ失敗を避けるため、次を守る。

- ODE 側にも速くする工夫を許す。刻み幅を粗くする、指数 Euler（ゲート変数の式を 1 ステップごとに厳密に積分する方法。HH 型の式では大きな刻みでも安定 [14]）、RK4、fp16・混合精度、`torch.compile` やカーネルの融合。
- 「同じ精度なら何倍速いか」と「同じ時間ならどちらが正確か」の両方を、精度と時間の図で示す。図の上で、どちらかを良くするともう一方が悪くなる点の集まり（Pareto 曲線）を比べる。流体の代理モデルでも、解像度を変えた数値解法を同じ図に並べて比べている [15]。HH の解法どうしを精度と CPU 時間で比べた例もある [24]。
- 精度の合格条件（例: Γ ≥ 0.9、発散なし）は測る前に決める。
- 負けた結果も載せる。HH の速度で、同時に計算するニューロンが多いとき（B = 65536 など）はこれに当たる。

### 0.4 統計の扱い

- テストを用途で分ける。26 本と追加 125 本は作り方を選ぶのに使ったので「探索用」とし、最終の報告には新しく作った固定のテスト集合を使う。指標、刺激の種類ごとの重み、発散したときの扱いも先に固定する。
- 学習の seed を 3〜5 本変えて、平均とばらつきを示す（提案）。
- 2 つのモデルの差は、同じ入力系列どうしを対にし、刺激の種類の中でブートストラップ（標本を復元抽出し直して統計量の分布を作る方法）した 95% 信頼区間で示す。

## 2. 学習（パターンごと）

共通事項は次の 3 つ。

- 初期状態は前走行から取る。209 変数を独立にランダムに選ぶと、生理的にありえない状態になるため。
- 標準化は学習集合だけで推定する。
- χ（Ca プール、任意単位）は値の幅が大きいので `log1p(χ/s)` などで圧縮する。

### RNN 3 個型（分割型）

1. 各ブロックを正しい状態を入力にして事前学習する（HH と同じ）。
2. 予測した rate とゲートをつなぎ、19 区画を同時に閉ループで学習する。損失は全区画の状態にかけ、細胞体の電位には追加の重みを置く（区画平均だと細胞体の誤差が埋もれる）。
3. rollout の長さを 1 → 10 → 100 → 1000 ステップと伸ばす（カリキュラム）。長い系列は勾配の計算を区切る。
4. 入力の雑音と多段の損失を比べる。雑音は Sanchez-Gonzalez et al. 2020 の考え方に基づく [6]。

### RNN 1 個型（丸ごと型）

1. 正解の V_soma を戻す教師強制から始め、予測を戻す割合を増やして、最後は閉ループで学習する。
2. 隠れ状態の次元 H = 32 / 64 / 128 を比べる。
3. Ca や樹状突起の状態が違っても V_soma は同じになりうる。そのため、既知の静止状態から始めるか、0.2〜1 s の I/V の履歴で隠れ状態を初期化する。初期化の後は正解の V を与えない。
4. このモデルは細胞体の入出力を代替するもので、全状態の再現とは区別して扱う [3, 4]。

### flow function

1. 209 次元の初期状態を encoder に、区分一定の電流と区間長を control-RNN に入れ、decoder で全状態を出す。
2. 1ステップの変化量ではなく、複数の時刻の状態を正解にする。
3. スパイク付近を残す棄却抽出と、短い窓をつなぐ windowed loss（Aguiar et al. 2024）から始める [5]。細胞体と樹状突起の両方のイベントを抽出の対象にし、静止区間も残す。
4. 出力する時刻の間隔が粗いと Na スパイクを見逃すので、別に確認する。

### 電位の損失（RNN 3 個型と RNN 1 個型）

全時刻の MAE または Huber 損失に、スパイク近傍の追加の重みを足す。重みは 1 / 3 / 10 を試し、閾値下の精度と両立するものを選ぶ。

## 3. 精度の評価

### 3.1 共通の条件

条件は全パターンで共通にする。同じ入力を使い、自己回帰で回し、途中で正解に再同期しない。長さは 1 s と 10〜30 s の2通りで、刺激の種類・発火様式ごとに集計する。正解は 0.2 節の 2 つを両方使う。

### 3.2 HH（移植前）

#### 今使っている指標（`experiments/hh_surrogate/hh_bench.py`、`hh_bench_ext.py`）

| 指標 | 定義 |
|---|---|
| スパイク本数 | V が 0 mV を下から上に横切った回数。（正解, 予測）の組で記録する |
| 一致率 | 正解の各スパイクに ±2 ms 以内の予測スパイクを 1 対 1 で対応させ、対応できた数 ÷ max(正解の数, 予測の数)。両方 0 本なら 1 |
| Γ | coincidence factor（許容幅 ±2 ms）。偶然の一致の期待値を引き、完全一致で 1 になるよう正規化する [7, 8] |
| RMSE | 全波形の二乗平均平方根誤差 [mV] |
| 発火率の誤差（f–I） | 定常電流 0〜30 µA/cm² の 61 本で、後半 500 ms の発火率の RMSE [Hz] と、反復発火が始まる電流 |
| 長時間の安定性 | 20 s で発散したか、前半 5 s と後半 5 s の Γ |

テストは 26 本（最終評価用）、検証 17 本（最良の時点を選ぶ用）、追加 125 本（f–I、seed 違い、20 s の長時間、学習範囲の外）。正解はすべて教師正解。

分かっている弱点: 定常電流を長く流すとスパイク時刻が少しずつずれる。遅いランプ電流で発火の始まる時刻がずれる。

#### 追加する評価（実装の軽い順）

| 優先度 | 何を測るか | どう測るか | なぜ必要か |
|---|---|---|---|
| 必須 | 収束正解に対する誤差 | 0.2 節の収束正解で、Euler（dt = 0.01 ms）と代理モデルの両方を同じ指標で採点する | 代理モデルの誤差が、Euler 法そのものの誤差の何倍かを言える |
| 必須 | 周期の誤差と波形の誤差を分ける | 定常電流で最初の過渡を除き、k 番目のスパイク時刻の差を k に対して直線で当てはめ、傾き（1 周期あたりのずれ [ms]）を出す。各周期を位相（周期の中の位置、0〜1）で揃えて V, m, h, n を比べる。スパイクの欠落・余分は別に数える | 「時刻が少しずつずれる」が周期のわずかな偏りだけで説明できるかを確かめる。例えば 10 µA/cm² 付近（約 70 Hz）で周期が 0.1% ずれると、1 s（約 70 周期）で約 0.07 周期ずれるので、長時間の Γ が下がるのは避けにくい |
| 必須 | 統計の扱い | 0.4 節（新しいテスト集合、学習 seed 3〜5 本、対にしたブートストラップの 95% 信頼区間） | 26 本で選んだモデルが、seed を変えると順位が入れ替わったため |
| 必須 | 発火の開始・停止電流と双安定 | 定電流を少しずつ上げる系列と下げる系列を、静止状態から始めた場合と発火中の状態から始めた場合で回す。反復発火が始まる電流・止まる電流と、静止と反復発火が共存する範囲を比べる（HH はこの共存範囲を持つ [16]） | 遅いランプで発火開始がずれる原因が、分岐点（振る舞いが質的に変わる電流）の位置のずれか、入力の履歴への依存かを切り分ける |
| 推奨 | 位相応答曲線（PRC） | 定常発火の周期の各位相に同じ短い電流パルスを入れ、次のスパイクが何 ms 早まるか遅れるかを測る。早まる・遅れるの符号と、切り替わる位相を比べる | 周期が合っていても、入力に対する時刻の応答が違うと OU 電流などで時刻がずれる。ネットワークに入れたときの同期のしやすさにも関わる |
| 推奨 | 特徴量ごとの誤差 | 初発潜時、ISI（スパイク間隔）、スパイクの高さと幅、AHP（スパイク後の過分極）の深さ。eFEL [18] で出せる。特徴量ごとに標準化してまとめる考え方は [17] | Γ と RMSE だけでは、どこが悪いのかが分からない |
| 推奨 | 時間尺度の要らないスパイク列の距離 | Victor–Purpura 距離・van Rossum 距離に加え、SPIKE 距離・ISI 距離 [19] | 許容幅 ±2 ms の選び方で結論が変わらないことを確かめる |
| 余裕があれば | 1 ステップ誤差と閉ループ誤差の関係 | 正解の状態から 1, 10, 100, 1000 ステップ回し、誤差がどう伸びるかを見る | どの状態で誤差が増えるかが分かる |
| 余裕があれば | 静止状態の安定性 | 一定電流で代理モデルの固定点（動かなくなる状態）を求め、1 ステップの写像を状態で微分した行列（ヤコビアン）の固有値を、同じ刻み幅の HH の写像と比べる | 発火開始のずれが、静止状態の安定性の違いから来るのかを確かめる |

### 3.3 Traub（移植後）

計画の初版で決めた観点は次の表の通り。

| 観点 | 指標 | 文献 |
|---|---|---|
| スパイク時刻 | 偶然の一致を補正した coincidence factor Γ（許容幅 ±1 / 2 / 4 ms）。無発火のときは誤発火数を示す | Kistler et al. 1997 [7]、Jolivet et al. 2008 [8] |
| スパイク列の距離 | Victor–Purpura 距離、van Rossum 距離（複数の時間尺度） | [9, 10] |
| 閾値下 | 両方の系列のスパイク周辺を除いた RMSE。全波形の RMSE も併記 | |
| 発火様式 | f–I 曲線、発火開始電流、初発潜時、ISI、バースト間隔、1 バーストあたりのスパイク数、バースト持続時間。バースト判定の ISI 閾値は教師データで固定し、感度も調べる | |
| 全区画（RNN 3 個型、flow function） | 19 区画の電位と Ca の誤差。樹状突起の Ca スパイクの発生率・開始時刻・幅と、細胞体のバーストとの対応 | RNN 1 個型では直接評価できない |

HH で使っている「±2 ms の一致率」は、Γ と同じ「時刻が近いスパイクを対応させる」考え方の簡易版なので、Traub では Γ に置き換える。

| 優先度 | 何を測るか | どう測るか | なぜ必要か |
|---|---|---|---|
| 必須 | 原著論文の図の再現 | Traub et al. 1991 [1] の図と同じ刺激を入れ、細胞体と樹状突起の波形を並べる。博論も原著論文の図との比較から始めている（[11] pp.34–35 図 3.4・3.5） | 数値で評価する前に、特徴的な振る舞い（バーストなど）が出ているかを示す |
| 必須 | 発火様式・刺激部位ごとの集計 | テスト集合を固定し、無発火・単発・反復発火・バーストごと、細胞体刺激・樹状突起刺激ごとに、モデル間の差と信頼区間を出す | 無発火の例が多いと、苦手な条件が平均に埋もれる |
| 必須 | 樹状突起にも収束正解を使う | 同じ 19 区画の式を fp64・細かい刻みで解き、細胞体のスパイクに加えて、区画ごとの Ca の立ち上がり時刻とピークが変わらなくなるまで確かめる | 粗い刻みの ODE や代理モデルが、局所の Ca イベントを落とす条件を見つける |
| 推奨 | 入力期間中だけの誤差 | 電位の誤差を、電流を入れている期間だけで計算した値も出す（博論の MSE と同じ。[11] p.33 §3.2.7） | 静止している区間が長いと誤差が薄まる |
| 推奨 | Ca スパイクから細胞体バーストへの伝わり方 | 樹状突起の刺激位置と強度を変え、最初に Ca イベントが起きる区画、区画間の順序と遅れ、細胞体がバーストに移る境界の電流を比べる | 数や振幅が合っていても、起きる場所や順序がずれる場合を見つける |
| 余裕があれば | 区画間の誤差の伝わり方 | 1 つの区画の V か Ca を少しずらし、ずらした場合とずらさない場合の差を、時間 × 区画の図で ODE と代理モデルについて比べる | 局所の誤差が細胞体へ増幅される条件が分かる |
| 余裕があれば | 簡略化した ODE との比較 | Traub を 2 区画に縮めた Pinsky–Rinzel モデル [2] を、精度と時間の図に 1 点置く | 「式を簡単にすれば速くなる」という反論への答えになる |

## 4. 速度の比較

- 同じ GPU・同じフレームワークで、バッチ化した Euler 法の版を用意する。まず FP32・dt = 0.01 ms で比べる。
- バッチサイズ B = 1, 8, 32, 128, 512, 2048, … について、十分なウォームアップの後、GPU の同期を挟んで繰り返し測る。
- 主な指標は neuron-seconds/s（B × 模擬時間 ÷ 実時間）。あわせて「1 s の軌道を 1 秒あたり何ニューロン計算できるか」も示す。
- 推論のみ、転送込み、記録込みを分けて測る。初期化の時間、メモリ、中央値とばらつきも報告する。
- Tensor Core 用の混合精度（HH では TF32・fp16 は可、bf16 は不可）、コンパイル、粗い時間刻みは追加の条件として、同じ精度での比較とは分けて示す。
- 最終的な判断は速度だけでなく、精度と速度の関係を示す曲線で行う [3, 4]。

### 4.1 時間計算量の評価方法

小林先生の博士論文 [11] 第 3 章の評価方法を手本にする。博論は GPU 上で陰解法（CN 法）を陽解法（RKC 法）に置き換えて高速化した研究で、「詳細モデルを GPU で速くする」という点で本研究と問題設定が同じ。

実行時間は次の 3 つの因子に分けて考える。

$$
\text{実行時間} \approx T \times c_{\text{step}} \times f(B)
$$

| 因子 | 意味 | HH・Traub（Euler） | 代理モデル（RNN） |
|---|---|---|---|
| $T$ | ステップ数（模擬時間 ÷ dt） | dt = 0.01 ms で固定 | dt を大きくできれば減る |
| $c_{\text{step}}$ | 1 ステップのコスト | 要素ごとの演算が中心。メモリ帯域で律速されやすい | 行列積が中心で $O(H^2)$（$H$: 隠れ層サイズ）。演算で律速されるが Tensor Core を使える |
| $f(B)$ | バッチ数 $B$ に対する伸び方 | $B$ が小さいうちは GPU を使い切れず、ほぼ一定 | 同じ |

博論では、硬いモデルで刻み幅が最小値に張り付いて $T$ が増え、CN 法より 4.5 倍以上遅くなった例（[11] p.38, p.44）と、RKC 法は演算回数が多いのにメモリ転送量が CN 法の 1/1000 未満で速かった例（[11] p.37 図 3.7）が示されている。どちらもこの 3 因子で説明できる。

測るもの:

1. **理論計算量**: 1 ステップあたりの演算数を、手計算と `torch.utils.flop_counter.FlopCounterMode` の両方で求める。全体のオーダーは HH・Traub が $O(B \cdot T)$（Traub は区画数 $C$ を含めて $O(B \cdot T \cdot C)$）、RNN が $O(B \cdot T \cdot H^2)$。FLOPs だけでは実際のコストを表せない [12] ので、次の実測で必ず裏付ける。
2. **B を変えた実行時間**: 横軸 $B$、縦軸 実行時間の図を、5 回の平均と標準偏差で描く（[11] p.36 図 3.6d と同じ形）。CPU 版も並べる。両対数で描き、傾きで実際のオーダーを、傾きが 0 から 1 に変わる $B$ で GPU が飽和する点を読む。
3. **計測の手順**: 一定時間のフリーラン（ウォームアップ）の後、決めた模擬時間ぶんを測る。初期値は静止状態から少しずらす（[11] p.33 §3.2.7）。
4. **メモリ転送量と演算回数**: Nsight Compute の `dram__bytes_read.sum`・`dram__bytes_write.sum` と演算回数を、短いシミュレーションで測る（[11] p.32 §3.2.6、p.37 図 3.7。博論の nvprof は新しい GPU では使えないため Nsight Compute で代用）。HH 単体で代理モデルが勝てない理由を、メモリ律速か演算律速かで説明する。
5. **実行時間の内訳**: RNN 本体、出力層、ホストとの転送、記録に分ける（[11] p.41 図 3.9c）。
6. **精度と速度のトレードオフ**: 隠れ層サイズ $H$ と dt を変え、横軸 実行時間、縦軸 Γ・RMSE の図を描く（[11] p.39 図 3.8d–f。博論は RKC の tolerance を変えている）。

計算環境（CPU、GPU、メモリ、OS、CUDA・PyTorch のバージョン）は表にまとめて載せる（[11] p.22 表 2.1）。

比較の相手（ベースライン）について: 本研究の Traub は陽的 Euler 法なので、各ステップで連立方程式を解く必要がない。NEURON などの陰解法では、各ステップで疎行列の連立方程式を解く。博論の CN 法では、ケーブル方程式の係数行列を CSR 形式（非ゼロ要素だけを持つ疎行列の格納方式）で持ち、cuSPARSE の疎行列ベクトル積と cuBLAS のベクトル演算で CG 法を回している（[11] 付録 A.3.1, pp.89–94）。このデバイスメモリへの読み書きが CN 法のボトルネックだった（[11] p.44）。陰解法のシミュレータと比べる場合は、この違いを「どちらの数値解法と比べたか」として明記する。RKC 法のように局所誤差の推定でベクトルの総和を取る処理は、Parallel Reduction（2 つずつ並列に足し合わせる方法。段数は $\log_2 n$）で実装されている（[11] 付録 A.3.2, pp.94–96）。代理モデルで全ニューロンの統計（平均発火率など）を毎ステップ取る場合も、同じ考え方で段数を見積もれる。

### 4.2 HH（移植前）

#### 損益分岐の刻み幅

具体例: 同じバッチ数で、代理モデルの 1 ステップが ODE の 300 倍かかるとする。ODE が dt = 0.01 ms で回っているなら、代理モデルは 1 ステップで 3 ms 以上進めないと追いつかない。

原理: 模擬時間 $T_{\text{sim}}$ を計算する時間は「ステップ数 × 1 ステップの時間」。

$$
t_{\text{ODE}} = \frac{T_{\text{sim}}}{\Delta t_{\text{ODE}}} \, c_{\text{ODE}}, \qquad
t_{\text{MLP}} = \frac{T_{\text{sim}}}{\Delta t_{\text{MLP}}} \, c_{\text{MLP}}
$$

代理モデルが勝つ条件 $t_{\text{MLP}} < t_{\text{ODE}}$ を変形する。

$$
\frac{T_{\text{sim}}}{\Delta t_{\text{MLP}}} \, c_{\text{MLP}} < \frac{T_{\text{sim}}}{\Delta t_{\text{ODE}}} \, c_{\text{ODE}}
$$

$$
\frac{c_{\text{MLP}}}{\Delta t_{\text{MLP}}} < \frac{c_{\text{ODE}}}{\Delta t_{\text{ODE}}}
$$

$$
\Delta t_{\text{MLP}} > \Delta t_{\text{ODE}} \cdot \frac{c_{\text{MLP}}}{c_{\text{ODE}}}
$$

$c$ は同じ GPU・同じバッチ数で実測した 1 ステップの時間。$\Delta t_{\text{ODE}}$ には dt = 0.01 ms ではなく、精度の合格条件を満たす最も粗い刻み（指数 Euler ならかなり大きくできる [14]）を入れる。こうすると代理モデルにとって条件は厳しくなるが、公平になる。今の Markov MLP は dt = 0.01 ms の増分だけを学習しているので、刻みを大きくした点には、その刻みで学習し直したモデルを使う。

#### 測るもの（実装の軽い順）

| 優先度 | 何を測るか | どう測るか | なぜ必要か |
|---|---|---|---|
| 必須 | 損益分岐の刻み幅 | 上の式。B = 1〜数千の各点で $c_{\text{MLP}} / c_{\text{ODE}}$ を実測して計算する | 何倍の刻みなら勝てるかを、学習する前に見積もれる |
| 必須 | 演算量とメモリ転送量（負ける理由） | `src/evaluation/opcost.py` と `FlopCounterMode` で演算数、Nsight Compute で DRAM 転送量を測り、ルーフライン図 [20]（横軸: 演算強度 = 演算数 ÷ 転送バイト数、縦軸: 達成した FLOP/s）に ODE と MLP を置く | ODE はメモリ転送で、MLP は演算量で速度が決まることを図で示せる |
| 必須 | ODE 側の精度と時間の図 | Euler・指数 Euler・RK4 × dt（0.005〜0.1 ms）× fp32/fp16 を、同じ GPU・同じ入力で回し、収束正解に対する Γ と実行時間を描く。合格条件を満たす最速の ODE を決める | 弱いベースラインを避ける [13]。上の損益分岐の $\Delta t_{\text{ODE}}$ もここで決まる |
| 推奨 | 両方を最大限速くした版 | ODE は eager（そのまま実行）、`torch.compile`、1 つの CUDA カーネルに融合した版。代理モデルは `torch.compile` と Tensor Core（fp16/TF32、`hh_fused.py`） | 片方だけ最適化すると不公平になる |
| 余裕があれば | 刻みを大きくした代理モデル | Δt = 0.1, 0.5, 1 ms の写像を学習し、精度と時間の図に置く | 損益分岐に届くかを実際に確かめる。HH で勝てる可能性があるのはこの条件だけ |

### 4.3 Traub（移植後）

| 優先度 | 何を測るか | どう測るか | なぜ必要か |
|---|---|---|---|
| 必須 | 209 状態を出す場合の損益分岐を先に見積もる | 幅 H の 2 層 MLP なら、1 ニューロン・1 ステップの線形層の演算は約 $2(D_{\text{in}} H + H^2 + 209 H)$ FLOP（$D_{\text{in}}$: 入力の次元）。例: $D_{\text{in}} = 210$、H = 256 なら $2(53{,}760 + 65{,}536 + 53{,}504) = 2 \times 172{,}800 = 345{,}600$ FLOP。Traub の 1 ステップを opcost で数え、4.2 節の式で必要な刻みを出す | 学習する前に、勝ち目があるかを判断できる |
| 必須 | 強い ODE ベースライン | `src/neuron/traub.py`（NumPy）を PyTorch のバッチ版に移し、融合カーネル版と指数 Euler 版も作る。ゲートの更新法と区画間の結合の扱いを明記する。余裕があれば区画間の結合を半陰的に解く版（樹状の区画の連立方程式を区画数に比例する手間で解く Hines 法 [21]）も加える | 細胞体のスパイクと樹状突起の Ca の両方で合格条件を満たす最速の ODE と比べるため |
| 必須 | 出力の範囲で条件を分ける | 全 209 状態、細胞体の V だけ、低次元の潜在状態、の 3 通りで時間を測る | 代理モデルの計算量は出力の次元で大きく変わる |
| 推奨 | ルーフラインと Tensor Core の実効性能 | 209 は 16 の倍数でないので、224 に 0 で埋めた場合と比べる。型変換、SiLU、状態の足し込みも含めて測る | Tensor Core が実際にどれだけ効いているかを確かめる |
| 参考 | 既存のシミュレータ | NEURON（CPU、陰解法）、Jaxley [22]（JAX で多区画モデルを GPU で解く）、Brian2CUDA [23] の値を、主な比較とは別枠で載せる | 実際によく使われる道具と比べてどの位置にいるかを示す |
| 余裕があれば | 区画数を変えたスケーリング | 同じ形を細かく分けた派生モデル（区画数 C を増やす）で、それぞれの収束正解に精度を揃えて時間とメモリを測る | 区画が増えるほど代理モデルが有利になるかが分かる |
